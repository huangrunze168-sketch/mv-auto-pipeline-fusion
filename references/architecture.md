# 架构设计

> **结论先行**：本方案以「纪律层」（十二步八道关）为骨架、「故事视觉开发 + 用户选择的外部后端适配 + 验证」为生成链、「skill 形态」（阶段独立、可续跑、ffmpeg 合成）为外壳。核心仓库不绑定任何视频服务商或模型。

## 一、分层架构（四层）

```
┌─────────────────────────────────────────────────────┐
│ 应用层 · 十二步编排（SKILL.md 流程）                    │
│   步骤状态机 → 每步产出落 state/，任意步可断点续跑        │
├─────────────────────────────────────────────────────┤
│ 纪律层 · 八道关（gate_checks.py + HTML 页面）           │
│   关1-4 结构关 · 关5/6 硬门禁 ⛔ · 关7/8 验收关          │
├─────────────────────────────────────────────────────┤
│ 领域层 · 数据模型（state/ 下的 JSON）                   │
│   timeline.json → style.json → storyboard.json        │
│   → prompts/SHxxx.json → clips/ → verification_report │
├─────────────────────────────────────────────────────┤
│ 基础层 · 工具（scripts/）                               │
│   crew_pipeline.py · film_grammar_corpus.py           │
│   duration_fit.py · align_verify.py · ledger.py       │
├─────────────────────────────────────────────────────┤
│ 外部适配层 · 用户选定后端（不在核心仓库内置）             │
│   实测 schema │ 模型原生编译 │ 提交回执 │ 成本与并发控制      │
└─────────────────────────────────────────────────────┘
```

## 二、模块职责总表

| 模块 | 职责 | 落点 |
|---|---|---|
| 音乐预处理 | 结构分段 / 歌词时间戳 / 音乐描述 | 步骤 1，ASR + 官方歌词校正 |
| 编剧 / 导演双 Agent | 出故事线与分镜画面，**切点/段长由 timeline 推导**（铁律 A 压过 Agent 自由发挥） | 步骤 4 |
| 生成职责 | 核心只标记 `generation_role=lip_sync|narrative`；用户可选择同一或不同后端，路由由外部适配层实现 | 步骤 7/8 |
| 验证 | 硬判据机器验 + LLM 软审（画质/一致性，不替代硬判据） | 关 7/8 |
| 可续跑与依赖 | 每步状态落 state/；重跑核对上游指纹，只复核受影响资产 | 项目目录与资产依赖 |
| ffmpeg 合成 | 逐段拼接 + 母带重贴音轨 | 步骤 10 |
| 纪律层 | 关 5/6 硬门禁写进代码，六铁律 = 可执行校验 | gate_checks.py |
| 电影语法参考 | 合法标注 → 匿名统计画像 → 项目节奏/转移审计；不保存正片，不把具体电影注入提示词 | 步骤 4/5 之间，可选 |

## 三、一次完整数据流（正常路径）

```
原曲 + 官方歌词 + 主人公图
  │
  ├─ 步1: ASR API → 逐行时间戳 → 与官方文本强制对齐
  │        └→ state/timeline.json（+导出 .lrc）【关1】
  ├─ 步2: 风格讨论 → state/style.json（含指纹）【关2】
  ├─ 步3: 主人公图指纹化上传一次（缓存复用）【关3，无主角跳过】
  ├─ 步4: timeline 推导段长/切点 → 编剧+导演 Agent 填画面
  │        └→ state/storyboard.json【关4】
  ├─ 步5: 六段式提示词派生 → prompts/SHxxx.json
  │        └→ gate_checks.py gate5：20 项机检 ⛔不过不提交【关5·硬】
  ├─ 步6: 窗口核对 → gate_checks.py gate6 ⛔【关6·硬】
  ├─ 步7: 拉真实节点表体检 + 首镜试产（实测契约/分辨率/音频策略）
  ├─ 步8: 批量生成（并发/续跑/在途救回）→ clips/
  │        └→ duration_fit.py 逐段贴合窗口长
  ├─ 步9: 主因诊断/定向修复（受影响依赖与提示词指纹失效 → 退回相应步骤）
  ├─ 步10: ffmpeg 拼接 → 成片×2 → align_verify.py 对齐三验【关7/8】
  ├─ 步11: 交付打包（成片/分镜表/lrc/验收报告）
  └─ 步12: 复盘三问 → 沉淀三处 → 发版
```

## 四、层间结合机制与依赖方向

| 结合点 | 机制 | 证据 |
|---|---|---|
| 应用层 → 纪律层 | 每步收尾调 `gate_checks.py` 子命令，退出码非 0 即阻断 | 关 5/6 硬门禁对应 `check_prompt` / `check_storyboard` |
| 纪律层 → 领域层 | 只读 JSON 校验，不修改数据（校验器无副作用） | gate5 只判 prompt JSON，不改写 |
| 应用层 → 基础层 | 脚本互不依赖、只依赖标准库 + ffmpeg，可独立单测 | align_verify.py 纯标准库 |
| 应用层 → 外部适配层 | 核心输出模型中立章节包；步骤 7 由用户选后端、实测 schema，再在仓库外转码与提交 | 铁律 D「不猜」 |

**依赖方向单向向下**，上层可替换（换生成 API 只动协议集成层），下层不知上层。

## 五、设计代价（明说，不藏）

| 代价 | 说明 | 缓解 |
|---|---|---|
| 关 5/6 在生成前拦一道 | 提示词不达标就要返工重写，节奏比「直接生成再看」慢 | 硬门禁挡的是白烧的 API 费，整体更省 |
| 全 API 无本地口型模型 | 口型精度依赖云端 API 上限 | 后端抽象层保留切换本地口型模型的口子（混合路线） |
| 人声能量检查用全混代理 | 有强伴奏时判据会变松 | 可选接人声分离 API 增强，schema 已预留字段 |
| 纯标准库对齐验证 | 无 scipy 精细窗函数 | 包络+局部搜索判据对「滞后≈0」足够，运算量万级 |
